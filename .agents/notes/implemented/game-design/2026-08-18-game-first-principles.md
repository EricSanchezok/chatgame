# Agent Note: 游戏第一性原理——剧本驱动的通用 AI 游戏框架

Status: implemented

## Problem

目标不是做一个"AI 聊天玩具"，而是一个真正的游戏：玩家通过聊天游玩，但世界必须真实、有规则、可长期游玩。

最直觉的做法是把所有内容塞进对话——让模型在文本里"假装"存在一个世界。这条路有四个根本问题：

1. **状态不可靠**：模型输出是概率性的。背包、血量、时间一旦只存在于对话文本，就会漂移、遗忘、自相矛盾。
2. **机制无法执行**：时间推进、战斗结算、属性增减需要确定性计算，文本里无法运行。
3. **无法通用**：每个游戏从零写逻辑，就做不到"换剧本即换游戏"。
4. **无法无限游玩**：没有真实的世界状态与持久化，长会话会超出模型上下文，"世界"无法延续。

## Decision

chatgame 是一个"剧本驱动"的通用 AI 游戏框架，由两条第一性原理定义。

**原理一：剧本即世界（脚本化 · 随机性 · 无限游玩）**

- 框架是通用的：世界观、背景、人物等一切内容由"剧本"（Script）定义。加载不同剧本 = 完全不同的游戏。
- 同一剧本每次开局体验不同：大模型的随机性不是缺陷，而是特性——每次重启都是一次新的世界。
- 剧本理论上可无限游玩：一个剧本就是一个世界，玩家在这个世界里生活，世界响应玩家的动作；没有固定结局。

**原理二：机制是真实数据（引擎管规则，LLM 管叙事）**

- 游戏不局限于对话：时间机制、角色机制、背包机制、战斗机制、生命值等，由一套通用的底层机制层负责管理与推进。
- 游戏状态是引擎管理的真实数据，不是对话文本。NPC 拥有自己的记忆与属性；角色、怪物等实体继承自通用底层类（如生命值、蓝量）。
- 这套底层机制让世界"既随机又符合规范"：LLM 生成叙事与行为（随机性/涌现），引擎执行规则与状态（规范性/一致性）。

三者关系：剧本决定"世界是什么"，机制层决定"世界如何运转"，LLM 决定"世界如何回应"。三者解耦，各自可替换、可扩展。

本决策已接受为设计基础；对应代码尚未实现，首次落地点是剧本格式与引擎核心。

## Alternatives considered

**纯对话方案（状态全部存在于文本）**。放弃。模型概率性输出导致状态漂移与自相矛盾；时间/背包/战斗无法确定性执行；长会话超出上下文后世界无法延续。

**每款游戏单独实现（无通用框架）**。放弃。与"换剧本即换游戏"直接冲突；机制无法复用，内容生态无法形成。

**固定剧情树（有限分支剧本）**。放弃。有限分支 = 有限体验，与"无限游玩"冲突；玩家遍历所有内容后游戏结束。本框架的剧本是"世界设定"，不是"剧情树"。

**引擎模拟一切（不用 LLM）**。放弃。NPC 的自然语言与世界的意外性无法靠手写覆盖；LLM 是随机性与叙事能力的来源。

## Consequences

代价：
- 引擎复杂度高：机制层必须足够通用，任意剧本都能配置或扩展。
- 剧本格式是核心契约：世界观、人物、机制配置的 schema 设计直接决定框架通用性。
- "无限游玩"带来工程问题：上下文管理、长期记忆、存档/读档、状态持久化。
- LLM 随机性需要约束：同一次游玩内 NPC 记忆与世界观必须自洽，需要引擎与记忆机制兜底。

收益：
- 一次开发，无限游戏：框架 + 任意剧本 = 新游戏，内容成本大幅降低。
- 真实感：状态真实、规则一致、世界记得玩家。
- 可测试：机制是确定性代码，可单元测试；LLM 只负责叙事，可替换、可降级。
