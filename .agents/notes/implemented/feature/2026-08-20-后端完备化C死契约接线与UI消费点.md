# Agent Note: 后端完备化 C — 死契约接线与 UI 消费点补全

Status: implemented

## Problem

调研发现一批"定义了但零消费"的契约：`action.cooldown`（动作冷却，schema 有、引擎不查）、`llm_freedom`（叙事自由度，schema 有、prompt 不注入）、`safety.yaml`（内容分级声明，loader 加载、系统 prompt 与 launcher 不展示）。同时一批"有实现无消费点"的后端能力没有 UI 闭环：`TurnResult` 的 `worldEvents`/`taskCompletions`/`deathFired`/`fellBackToTalk` 字段、描述层（descriptor）展示与编辑、`advance` 快进路由。另有一处安全缺口：zip 导入只限 zip 本体 20MB，未限解压总量（zip 炸弹可撑爆磁盘）。用户决策：死契约接口不删除，接线为真功能。

## Decision

- `action.cooldown` 接为引擎规则：`checkActionLegality` 在 `state.actionCooldowns[actionId]` 距今未满 cooldown 天时返回机器 reasonCode `on_cooldown`；`resolveAction` 成功结算后写入当前绝对天。`WorldState` 新增 `actionCooldowns: Record<string, number>`，`SAVE_SCHEMA_VERSION` 升到 **4**（与蓝图 B 的 `contextSummary` 相加性合入），`normalizeWorldState` 对旧档缺失字段补空对象。`narrativizeRejection` 消费 `on_cooldown` 输出世界一致文案（I7 模式）。
- `llm_freedom` 注入叙事 prompt：新增 `buildActionFreedomBlock(actionId, def)`，按 narration/process/result 三态返回中文语义指引块，措辞固定"机制由引擎结算，你只负责叙事"，绝不授予判定权（I4/I5 不变量）。`buildTurnPrompt` 在"输出要求"前、`actionId` 存在时插入"当前动作"块；`narrative.ts` 的 `generateNarrative` 传入 `resolution.actionId`。
- `safety.yaml` 轻量落地：`buildSystemPrompt` 末尾追加"内容边界（必须遵守）"块（age_rating、allowed 各内容类强度逐条、forbidden 列表，强度词直接引用剧本声明值，不新增枚举）；`GET /api/scripts/:id` 返回 `safety: { age_rating, content_classes }`；`ScriptSummary` 同步带 safety；launcher 剧本卡片标题旁展示 age_rating 徽标。生成后内容拦截留 V2。
- UI 消费闭环（全部复用 `--cg-*` 变量，零硬编码色）：
  - `chat.tsx` 新增 `SystemFeedbackBlock`：每回合 world 条目后展示 worldEvents 列表（🌍）、taskCompletions（✓/✗）、deathFired 提示条、fellBackToTalk 兜底小字。
  - `panels.tsx`：关系面板行显示 `descriptor.label + description`，行内"编辑"→ textarea → 保存调 `POST /descriptor`（`api.setDescriptor`）；角色/任务面板放"快进"控件（+1h/+6h/+1d，两次点击确认，调 `api.advance`）；`ActivePanel` 接收 `PanelHandlers`。
  - `state.tsx`：新增 `updateState` reducer action 与 `advance`/`updateDescriptor` 方法，更新后标记 dirty。
- zip 安全加固：`script-import.ts` 导出 `MAX_UNPACKED_BYTES = 100MB`，`extractZip` 解压循环在写出前累计 `Buffer.byteLength`，超限抛 `ScriptImportError` 并走现有失败清理路径；`importScriptFromZip` options 参数化 `maxUnpackedBytes` 供测试注入小上限。
- 保留不删（用户决策）：`EngineHost.scriptSaves()`、`mediaProvider` getter 等无消费方法保留，补 JSDoc 标注"内部保留 API，供未来调用方使用"。

## Alternatives considered

- **删除死契约字段（llm_freedom/cooldown/safety）**：用户决策"死契约接口不要删除，未来可能有用"，且接线成本低、可测。拒绝删除。
- **safety 完整执行管道（生成后分类拦截）**：文档自认 V2 工作；本次只做声明注入 + 展示，伪造执行违反"干净单一"。拒绝。
- **llm_freedom 授予 LLM 判定权**：违反 I4/I5（判定永远引擎侧）。接线为叙事指引，明确不越权。
- **UI 大改（独立死亡界面/任务中心/动作快捷栏）**：超出"最小消费闭环"；本次用聊天内系统条目 + 面板行内编辑，完整 UX 另开蓝图。
- **cooldown 存 eventLog 推导**：log 可裁剪不可靠；显式 `actionCooldowns` 字段最清晰。
- **advance 控件放 header 全局**：与面板冲突；放侧边栏面板区，与描述编辑同面板，消费点集中。
- **zip 上限做成配置项**：当前单机场景常量足够；参数化留给未来（options 已支持覆盖）。

## Consequences

- 三个死契约成为真功能：冷却动作在冷却期内被拒绝且文案世界一致；llm_freedom 出现在叙事 prompt 且不赋予判定权；safety 分级进入系统 prompt 与 launcher 展示。
- 存档 schema 升到 v4（与蓝图 B 协调，终值 4），旧档按敏捷约定拒绝，不写迁移。
- UI 可查看/编辑关系描述（双轨：只改 description、置 userEdited、不碰 value），可快进世界时间（不可撤销，带确认）。
- zip 导入拒绝超大解压（100MB 上限），防 zip 炸弹撑爆磁盘。
- 无消费方法保留并标注，行为不变。
