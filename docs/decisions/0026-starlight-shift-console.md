# 《星港》老站值班与资源事故重做

## Status
Deprecated
Class: feature

## Context and Problem Statement

《星港》的任务、声望、访问控制、世界规则和资源经济存在断路，HUD 使用本地假时间和默认数值。空间站 AI、黑客、管委会与冷蓝霓虹只是类型标签，没有形成劳动制度、资源分配和玩家责任。

## Decision Drivers

- 玩家是当班处置员，而不是无条件拥有权力的舰长。
- 每次事故提供多种真实路径，并在资源、权限、关系和追踪热度上产生后果。
- 灯塔 AI 的历史分配规则成为系统冲突，而非背景秘密。
- 视觉和声音表现老旧民用基础设施与交班仪式。

## Considered Options

- 修复现有任务并保留通用赛博 UI。
- 改成线性 AI 阴谋冒险。
- 重做为老旧空间站值班台与资源事故处置的系统型世界。

## Decision Outcome

玩家以维修二班值班员身份，在交班事故、移动与现场检查、维修/绕行/交易、确定性结算和下一班次反馈之间循环。灯塔依据两百年前的 `REG-2178` 登记册分配生存优先级；首个 P-07 空气净化事故提供三条可签结路径：消耗库存与电网的标准维修、消耗 EVA 氧气并增加船体/审计风险的舱外旁路、支付工分并留下审计痕迹的配给例外。三条路径都恢复册外住户供气，但下一班反馈不同。

船体、电网、供给、疲劳、EVA 氧气、追踪热度和灯塔分配只存在于星港扩展与 `runtimeState`。剧本通过 UI API v6 的 `GamePresentation` 提供 P-07 动态目标与建议行动，并注册站区剖面、工单、工装资源和无线电/事故档案，所有读数来自服务器权威状态。舱段、无线电、事故和维修结果进入宿主消息流；剧本不注册 `game-shell`、HUD、工具栏、composer 或暂停菜单。

视觉采用老旧公共设施而非科幻驾驶舱：炭灰与奶油白构成阅读底色，低饱和青绿表达维护与社区，琥珀只表示可操作供给，危险红只在真实故障出现。世界感来自维修标签、热敏交班记录、货运喷字和有人生活过的民用设施，不来自冷蓝霓虹、满屏终端、玻璃卡或装饰扫描线。HUD 是紧凑的“当班摘要”，无线电、事故警告、维修结果和普通叙述各有克制的消息节奏。四个舱段、P-07 事故与三名岗位角色使用不同的本地 WebP，避免通用太空站概念图；OGG 环境音和所有素材逐文件记录来源。当前范围是维修身份、居住/货运/维修/EVA 四区、老周/林小北/阿岑三名岗位角色和一个三解事故的 vertical slice；新增事故或身份必须复用同一权威资源循环，不能另建文本状态。

## Pros and Cons of the Options

### 修任务并保留旧表现

- 好：交付快。
- 坏：玩家身份、世界制度与交互仍然模板化。

### 线性 AI 阴谋

- 好：主线清晰。
- 坏：系统只服务一次揭露，无法支持长期值班循环。

### 系统型值班世界

- 好：事故、社会秩序、资源和身份路径持续互相影响。
- 坏：需要可靠的任务、权限、旅行和周期模拟。
