# 《星港》老站值班与资源事故重做

## Status
Proposed
Class: feature

## Context and Problem Statement

《星港》的任务、声望、访问控制、世界规则和资源经济存在断路，HUD 使用本地假时间和默认数值。空间站 AI、黑客、管委会与冷蓝霓虹只是类型标签，没有形成劳动制度、资源分配和玩家责任。

## Decision Drivers

- 玩家是当班处置员，而不是无条件拥有权力的舰长。
- 每次事故提供多种真实路径，并在资源、权限、关系和追踪热度上产生后果。
- 灯塔 AI 的历史分配规则成为系统冲突，而非背景秘密。
- 视觉和声音表现老旧民用基础设施与交班仪式。

## Considered Options

- 修复现有任务并保留通用赛博 UI。
- 改成线性 AI 阴谋冒险。
- 重做为老旧空间站值班台与资源事故处置的系统型世界。

## Decision Outcome

玩家在交班事故、现场调查、维修/绕行/交易、确定性结算和下一班次反馈之间循环。灯塔依据两百年前的登记册分配生存优先级，维修、货运和逃亡三种出身以合法权限、互助供应和系统入侵处理同一冲突。

船体、电网、供给、疲劳、EVA 氧气、追踪热度和灯塔分配只存在于星港扩展与 `runtimeState`。剧本通过 UI API v3 提供站区剖面、无线电/事故日志、成本预览、工种标签和资源告警，所有读数来自服务器权威状态。

视觉采用磨损的 Shift Console：暖灰、奶油、琥珀、低饱和青绿和明确危险色，配合维修挂牌、货运喷字与热敏交班记录；避免冷蓝霓虹、玻璃卡和装饰性扫描线。先交付维修出身、四个区域、三 NPC 和一个三解事故的 vertical slice。

## Pros and Cons of the Options

### 修任务并保留旧表现

- 好：交付快。
- 坏：玩家身份、世界制度与交互仍然模板化。

### 线性 AI 阴谋

- 好：主线清晰。
- 坏：系统只服务一次揭露，无法支持长期值班循环。

### 系统型值班世界

- 好：事故、社会秩序、资源和身份路径持续互相影响。
- 坏：需要可靠的任务、权限、旅行和周期模拟。
