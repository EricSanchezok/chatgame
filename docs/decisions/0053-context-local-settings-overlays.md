# 上下文内设置弹层与单一模态壳

## Status

Accepted
Class: simplification

## Context and Problem Statement

[0052](0052-persistent-game-context-and-world-library.md) 将游戏内存档和设置放入持久游戏布局上的大型管理层，但游戏外设置仍由独立 `/settings` 页面承载。同一份设置内容因此拥有全页与弹层两套导航壳；主菜单打开本机偏好会产生不必要的页面切换，游戏管理层又同时提供侧栏底部返回和右上角关闭。设置行的尾部控件按右边缘对齐，宽度不同的 switch 与按钮没有共同中心线；浏览器默认滚动条还在弹层边缘绘制持续可见的轨道。

设置是短暂、可撤销且不改变资源上下文的本机偏好操作。游戏外打开设置必须保持主菜单，游戏中打开设置必须保持当前会话；两处应复用同一内容和同一模态基础设施，而不是维护两个页面。

## Decision Drivers

- 主菜单打开设置时 URL 和主菜单状态保持不变。
- 游戏中的 assistant-ui runtime、composer、SSE 与 WorldRun 在设置期间继续存活。
- 主题、文字大小、减少动态效果和控制球复位只有一个内容实现。
- 每个模态层只提供一个视觉退出控件，并支持 Escape、遮罩关闭、焦点约束与焦点恢复。
- 不同宽度的尾部控件共享稳定中心线，设置行在窄屏和大字号下仍不横向溢出。
- 可滚动弹层只显示窄滚动拇指，不绘制持续可见的滑轨。

## Considered Options

- 保留游戏外 `/settings` 页面和游戏内设置管理层。
- 使用全局拦截路由，让 `/settings` 在软导航时显示为弹层。
- 主菜单使用本地 Dialog，游戏内保留持久布局下的嵌套管理路由，两处共享设置内容和模态基础组件——所选路线。

## Decision Outcome

本记录取代 [0052](0052-persistent-game-context-and-world-library.md)。其中世界包工作台、存档层级、assistant-ui 会话、WorldRun External Store、三动作控制球、非包围式焦点和游戏内嵌套管理路由契约保持不变；本记录重新定义设置入口和管理层通用几何。

游戏外公开路由只有 `/`、`/worlds` 与 `/worlds/:worldId`。主菜单的“设置”是按钮，在当前 `/` 上打开具备模态语义的设置 Dialog；独立 `/settings` 路由不存在。游戏内设置继续由 `/play/:sessionId/manage/settings` 精确寻址，并由 `/play/:sessionId` 持久布局托管，直接访问该地址也重建同一游戏背景。

`SettingsPanel` 是本机偏好的唯一内容实现。主菜单 Dialog 和游戏管理层只负责上下文、标题、尺寸和焦点恢复。遮罩、表面、右上角关闭控件和滚动区域使用共享模态基础样式；每个表面只有一个视觉关闭动作。滚动区域使用透明轨道和窄拇指，内容滚动不改变弹层宽度或右侧留白。

设置行由说明列和固定宽度的尾部控件列组成。switch 和“重置位置”按钮在尾部列内水平居中，因此控件宽度变化不改变共同中心线；窄屏缩小尾部列但保留至少 44px 的操作目标。

### Consequences

- 主菜单设置不产生历史记录或可分享 URL；刷新关闭弹层但保留已保存偏好。
- 游戏内管理 URL 继续支持刷新恢复和浏览器历史，且不卸载会话。
- 删除独立设置页面及其返回导航、页面级样式和测试路径。
- 共享模态壳约束两种上下文的退出、滚动和 forced-colors 行为，设置内容不感知自己位于哪一种容器。

## Pros and Cons of the Options

### 保留两套设置容器

- 好：无需改变主菜单入口或现有路由。
- 坏：短暂偏好操作打断游戏外上下文，并持续维护全页与弹层两套视觉和退出规则。

### 全局拦截路由

- 好：软导航可以保留可寻址地址并显示弹层。
- 坏：硬刷新需要另一套全页回退，重新制造双容器；本机偏好也没有需要分享的资源身份。

### 上下文内弹层与共享内容

- 好：入口语义与用户心流一致，偏好逻辑和模态基础设施各自只有一个实现。
- 坏：游戏外设置不再拥有独立 URL，刷新会关闭弹层。
