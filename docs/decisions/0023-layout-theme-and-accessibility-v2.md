# 布局、主题与无障碍表现契约 v2

## Status
Superseded by [0028](0028-conversation-first-game-layout.md)
Class: feature

## Context and Problem Statement

固定三区壳、居中模态和有限主题 token 无法覆盖窄屏、短横屏、文字缩放、深度剧本布局和完整交互反馈。旧实现缺少焦点陷阱、焦点恢复、背景 inert、实时区域和稳定的减少动效语义，主题也缺少前景、焦点与状态色角色。

## Decision Drivers

- 玩家在桌面、移动和放大文本环境中都能完成相同任务。
- 剧本视觉差异不能破坏语义状态、对比度和输入可达性。
- 动效表达因果与世界材料，并尊重用户偏好。
- 宿主界面在没有剧本扩展时仍完整可用。

## Considered Options

- 继续固定三区布局并增加少量媒体查询。
- 允许剧本注入任意全局 CSS。
- 采用宿主安全区域与语义 token、剧本可排布区域 renderer 的组合。

## Decision Outcome

宿主持有页面安全区域、portal、焦点顺序、Dialog 行为、实时播报和最小触控尺寸。`game-shell` 可以排列宿主提供的舞台、转录、操作区与面板 renderer，但不能绕过这些边界。

主题以 `--cg-*` 语义变量表达背景/表面/主次前景、主操作及其前景、焦点、边界、成功、警告、危险和选中状态。剧本组件不得硬编码颜色。字体、密度、文字缩放、对比度与动效偏好由宿主统一应用；减少动效只移除装饰性和空间移动，不移除必要的按压、等待和结果反馈。

布局基线覆盖窄屏、平板、桌面、短横屏、安全区和 200% 文字。主要目标最小 44×44px，正文与控件达到 WCAG 2.2 AA；颜色之外必须有标签、图标或形状表达状态。

## Pros and Cons of the Options

### 固定布局加媒体查询

- 好：保持现有组件结构。
- 坏：无法容纳两个剧本不同的信息架构，也无法修正模态和文字缩放的系统问题。

### 任意全局 CSS

- 好：剧本作者自由度最高。
- 坏：可破坏宿主焦点、可读性、其他剧本和状态语义。

### 安全宿主与语义表现契约

- 好：剧本可形成独特布局，同时共享可访问性与响应式底线。
- 坏：需要更多 view-model、区域 renderer 和视觉矩阵测试。
