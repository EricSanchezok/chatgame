# LLM 游戏中玩家自由文本动作的约束与防作弊：实践调研报告

> 调研日期：2026-08-18 ｜ 调研者：research-scout（为 chatgame 引擎设计提供依据）
> 目标读者：chatgame 主 agent 与架构决策者
> 结论速览：业界共识是"**LLM 建议、引擎裁决**"——玩家自由文本先被映射为结构化动作/效果提议，经程序化验证后由引擎结算，LLM 只负责叙事化描述引擎已结算的结果。把规则裁决交给 LLM（即使提示词写满禁令）已被 2026 年的基准证明不可靠（CoC-Seduce，见 §4.3）。

---

## 一、调研范围

### 1.1 核心问题

chatgame 是剧本驱动的 AI 聊天游戏：玩家用自然语言游玩（"我要偷东西""我要瞬移""我要开挂"），引擎管真实状态（时间/背包/血量/记忆），LLM 管叙事。核心矛盾：**如何让玩家有无限叙事自由，但状态/机制不被文字作弊破坏**。

本次调研覆盖五个子问题：

1. **结构化动作空间**：玩家意图必须映射到预定义动作集的做法（Bounded Autonomy、PA-POMDP、行为树→校验→执行）。
2. **效果来源约束**：玩家/LLM"声称"的效果 vs 引擎"结算"的效果如何分离。
3. **世界规则强制**：world rules 如何由引擎强制执行，规则检查在动作管线中的位置。
4. **叙事层拒绝与合理化**：超模请求在叙事上如何处理，世界边界指令如何设计。
5. **意图解析失败的兜底**：歧义/非法/超模输入的处理（拒绝/降级/重问）。

### 1.2 方法

- 来源类别：arXiv 论文（2020–2026，含 2026 年最新）、工程实践博客、产品官方文档、经典游戏设计文献（MUD/文本冒险解析器）、安全社区（OWASP LLM 注入）。
- 优先一手来源：论文原文（arXiv HTML 全文）、官方文档；工程实践以作者自述为准。
- 时效标注：所有结论标注来源时间；2026 年的新证据（CoC-Seduce、Orchestrated Reality、IVIE）优先采信。

## 二、结构化动作空间实践

### 2.1 Orchestrated Reality：Parameterized-Action POMDP + PDVA 管线（相关性：**高**）

**来源**：arXiv 2606.16014，2026-06，东京大学（进行中工作）。

**做法**：把 LLM 驱动的游戏世界形式化为"参数化动作 POMDP"：
- 状态 s 是**磁盘上的 JSON 实体树**（城镇、NPC、任务、玩家档案都是 schema 化的 JSON 文档），可检查、可 diff、可按内容哈希寻址。
- 动作 a = (k, x_k)：**离散意图种类 k**（move/speak/give/inspect…）+ **结构化 JSON 参数 x_k**。
- 玩家只能看到叙事投影 o = O(s)，不能直接看到/写状态。
- 转移核 F 是 **Plan–Diff–Validate–Apply（PDVA）** 管线：LLM 返回（叙事文本, 结构化状态增量 Δt）；每个增量必须通过 `Valid(δ) = SchemaOK(δ) ∧ PermOK(δ, actor) ∧ RuleOK(δ, ℛ)`；通过的增量原子提交，状态内容哈希（SHA256）记录进事件溯源日志。

**关键设计点**：
- 权限是 **deny-first** 的读写 glob（每个 actor 有自己的可写子树），"世界拥有世界"是引擎检查的不变量，不是 prompt 请求。
- LLM 被降级为"提议者"：它只提出 delta，真正的状态变更由验证管线决定——"**验证作为转移守卫，防止散文静默修改状态**"。
- 事件溯源 + 内容哈希让每次状态变更可审计、可回放。

**优劣**：
- 优：状态一致性与可审计性最强；叙事与状态严格分离（叙事是观察投影，不是状态）；形式化清晰，可直接借鉴。
- 劣：schema 覆盖之外的世界细节会漂移（论文自述：NPC 缺的手指在 24 回合里左右手互换）；规则集 ℛ 不完备；仅一个小规模试玩（N≈5，3 个月），玩家体验结论未验证；成本高（每回合多模型调用）。

**对我们的启示**：chatgame 的"引擎管状态、LLM 管叙事"与 PDVA 完全同构。可以直接采用"动作 = (意图种类, 结构化参数) + LLM 只提增量 + 引擎三关卡验证 + 原子提交"这套骨架；内容哈希/事件溯源对防作弊审计很有价值（但可按需简化）。

### 2.2 PAYADOR：预测结果而非映射动作（相关性：**高**）

**来源**：arXiv 2504.07304，2025-04，乌拉圭共和国大学等，开源（GitHub: pln-fing-udelar/payador）。续作：World-State Transformations (arXiv 2605.24719)、IVIE (arXiv 2606.13348)。

**做法**：经典世界更新问题是"把玩家输入映射到预编程动作"，这限制自由意志。PAYADOR 反过来：**不建模"玩家能做什么"，而是建模"世界如何变化"**——LLM 以最小结构化世界表示（item/location/character，关键属性结构化、其余用描述字符串）为输入，预测动作的结果（changes in the world），再把这些变化映射为对世界状态的更新。

**关键验证**：论文复现了 AI Dungeon 的经典反例（玩家坚称背包里有 bazooka，AI Dungeon 最终承认它可用）。PAYADOR 的 LLM 也预测"bazooka 现在在大厅"，但**一致性检查发现玩家背包里没有 bazooka，世界状态不变**，且错误不会污染后续回合（下一回合从结构化状态重新渲染）。

**优劣**：
- 优：自由度最高（任何动作都可"预测结果"）；轻量；一致性检查拦截了最常见的 LLM 幻觉改状态。
- 劣：LLM 常识推理失败——测试中玩家无钥匙成功进入上锁的厨房，说明**LLM 预测结果本身不可靠**，必须有更强的规则检查（IVIE 论文确认了这一缺陷，见 §2.5）。

**对我们的启示**："预测结果"是比"枚举动作"更优的自由度方案，但**不能把规则裁决交给预测 LLM**——LLM 预测的"效果"必须再过程序化规则（有没有钥匙、锁没锁）。chatgame 的意图分类层可以借鉴"输出结构化变化"的格式，但验证层必须独立。

### 2.3 STORY2GAME：动态生成动作（相关性：**中-高**）

**来源**：arXiv 2505.03547，2025-05，佐治亚理工（Riedl 组）。

**做法**：先用 LLM 生成故事、填充世界、**为动作生成引擎代码**（preconditions + effects），玩家动作由引擎执行；玩家想做故事外动作时，动态生成新动作并**动态更新引擎状态表示**。

**警示（对本次调研最重要的一句）**：论文明确承认该模式让"玩家几乎可以做任何事，包括**按世界逻辑明显不可能的事（没有任何先兆就能飞）**，或**破坏叙事流的事（立即杀死反派）**"——这是 LLM 生成动作/效果时自由失控的证据。

**优劣**：优——动作空间不封顶；劣——生成的 preconditions/effects 缺乏严格校验时，世界逻辑可以被玩家文字直接击穿。

**对我们的启示**：chatgame 若支持"剧本外新动作"，必须为动态动作的 preconditions/effects 设置程序化校验，否则等于向玩家开放世界规则编辑权。建议首版不做动态动作生成，先固定动作原语 + 参数引用已有实体。

### 2.4 Generative Agents：行为树计划 + 引擎执行（相关性：**中**）

**来源**：Park et al., UIST 2023（Generative Agents: Interactive Simulacra of Human Behavior）；Orchestrated Reality 将其定位为"无人类玩家的 LLM 世界"，Voyager/MineDojo 为"固定 Minecraft 世界中的 LLM 策略"。

**做法**（基于论文与二手引用，中置信）：agent 的每日计划是**行为树**，每回合通过检索选择相关计划子树并展开为具体动作；**动作由游戏沙箱引擎执行**（移动、睡觉、与对象交互），LLM 不直接修改世界状态。论文同时指出 agent 易受 **prompt/memory hacking**（内存注入攻击）。

**优劣**：优——"LLM 规划、引擎执行"分层清晰，动作是原子、可验证的；劣——动作空间小、表达力有限，且记忆注入是已知弱点（对 chatgame 意味着：**玩家文本不应能写入记忆**，记忆写入必须是引擎通道）。

**对我们的启示**：支持"行为树→校验→执行"作为未来复杂 NPC/玩家动作编排的参考；同时把"记忆只由引擎写"列为防作弊基线。

### 2.5 IVIE：增量验证生成的神经符号方案（相关性：**高**）

**来源**：arXiv 2606.13348，2026-06（PAYADOR 组续作）。

**做法**：四阶段增量生成可玩的交互小说世界，玩家动作经"推理 LLM 生成结构化状态变换 → **验证后才应用** → 叙事 LLM 描述新状态"的连续接地循环。

**关键发现（对本次调研最重要）**：论文报告 **LLM 推理模型会提出符号引擎应接受的非法状态变化（如把阻塞通道标记为可通行），即使前置条件未满足——"这类似越狱（jailbreaking）"**，该问题在 PAYADOR 原实现中同样存在。并总结出根本张力：**验证过严限制 LLM 生成自由，验证过松让玩家绕过谜题逻辑**。

**对我们的启示**：这是"LLM 提议 + 符号引擎验证"路线的最直接证据——**验证器本身必须是规则完备的程序化检查器**，不能是另一个 LLM（CoC-Seduce §4.3 给出更硬的证据）。

### 2.6 PWIM：意图→动作映射与分类纠错（相关性：**中**）

**来源**：arXiv 2406.00942，2024-06，Max Kreminski（Play What I Mean）。

**做法**：用轻量句子嵌入模型把玩家高层意图（短自由文本）匹配到具体游戏动作，**并在 UI 上允许玩家绕过分类错误**（候选动作列表让玩家选/改）。

**优劣**：优——承认意图分类有噪声并给玩家纠正通道；本地模型便宜；劣——动作空间仍封闭。

**对我们的启示**：意图分类置信度低时"让玩家确认/选择"是比"直接拒绝"更好的兜底（详见 §6.2）。chatgame 可在低置信时展示"你是指：偷窃/观察/交谈/离开？"。

### 2.7 其他：G-KMS、Inworld、行为树工具（相关性：**中**）

- **G-KMS**（MDPI Systems 14(2):175，2026-02）：RPG 的 schema 约束 LLM 管道——**JSON-only 解码 → 归一化 → 验证 → 合法任务才成为可执行 artifact**。与 PDVA 同族，确认"schema 约束生成"已是 2026 年工业界方向。
- **Inworld AI Runtime**（官方文档，2026-07 更新）：LLM node + 工具调用 + JSON 结构化输出，文档明确 LLM 用于"determine in-game actions"；动作落地走 graph 节点管道（确定性节点与 LLM 节点可混合编排）。未直接抓到 Inworld 官方的"Bounded Autonomy"完整页面，其动作落地的确定性层细节以官方文档为准，标注为**部分验证**。
- **"Bounded Autonomy"概念**（Cobus Greyling 2026-02 文章，企业 agent 视角）：受控自主 = 预定义工作流 + 沙箱权限边界，"真正的能动性来自受限边界内的独立，而非无限自由"。概念与游戏侧共识一致，可作文档引用。

**小结（三种范式光谱）**：
1. 全预定义动作集（经典 MUD/IF）——最稳但最不自由；
2. 意图映射到预定义动作集（PWIM、G-KMS、Inworld 管道、PA-POMDP 的意图层）——**业界主流**；
3. 开放结果预测（PAYADOR/IVIE）——最自由，但验证必须程序化，否则被 LLM 越狱击穿。
chatgame 应落在 2 为主、3 为辅（高置信短文本可走结果预测，但一律过程序化验证）。
