# 状态线与设置分隔累积

## Executive summary

世界演化页签把全局 `:focus-visible` 底部 box-shadow 和局部选中伪元素叠成两条蓝线，设置面板则让外层 fieldset 与内层 row 同时绘制分隔线并累加 padding。两处都没有阻断操作，却让状态和层级显得重复、松散。既有测试分别验证焦点存在、控件对齐和整页视觉大轮廓，没有断言一个状态只能有一个装饰来源，也没有检查嵌套分组的分隔数量与组内/组间距。持久修复移除全部底部状态线，用中性键盘焦点周界保留可达性，并把设置层级改为空间与浅层表面；回归直接读取伪元素、box-shadow、border 和几何间距。

## Summary

详情页签的选中背景本已足以表达当前页，但共享焦点规则又在控件底边绘制整宽蓝线，页签自身再绘制一条短线。设置页的开发者 fieldset 底边、内部 row 底边和相邻重置 row 底边连续出现，两个层级各自的纵向 padding 又把说明与控件推远。用户在真实桌面弹层中同时看到了重复状态线、连续分隔线和异常垂直节奏。

## Timeline

1. 普通非文本控件采用短底部焦点标记，以避免大面积包围式焦点框。
2. 世界演化详情页签独立增加选中伪元素，没有复用或替代共享状态表达。
3. 设置面板复用通用 fieldset 与 setting row，每层都默认拥有底部边界和纵向 padding。
4. 功能测试确认页签键盘导航、switch 写入和尾部控件中心对齐；视觉快照只覆盖世界演化整页，没有设置面板局部基线。
5. 用户截图显示页签同时出现长短两条蓝线，并指出开发者工具与重置位置附近的横线和间距混乱。

## Root cause

焦点、选中和分组都被实现为可自由叠加的局部 CSS 装饰，没有“一个状态一个视觉来源”和“空间优先于分隔线”的共享约束。全局焦点规则不了解组件已有选中背景，组件伪元素也不了解全局焦点几何；嵌套设置结构则让 fieldset 与 row 各自正确的单层样式在组合后变成重复层级。

测试继续验证单个机制而非组合结果。Axe 能确认焦点语义存在，却不会判断两条装饰线是否重复；尾部中心线测试不会发现上下间距；整页像素容差又足以吞掉局部 2px 线条。缺少设置桌面/窄屏视觉基线，也让连续分隔线没有专属门禁。

## Guardrails

- [决策 0056](../decisions/0056-control-state-and-settings-grouping.md) 固定无底部状态线、中性 2px 键盘焦点周界和设置空间分组。
- [全局样式](../../src/app/globals.css)只有一个普通主题焦点实现；详情页签没有选中伪元素，设置 fieldset 与 row 的底部边界宽度为零。
- Playwright 聚焦选中详情页签后读取 `box-shadow`、`outline` 和 `::after`，要求无阴影、无伪元素且仍有至少 2px 可见 outline。
- 设置流程读取所有 fieldset/row 的底边宽度，并验证开发者说明与控制行的组内间距；桌面与 390px 设置视觉基线覆盖明暗主题。
