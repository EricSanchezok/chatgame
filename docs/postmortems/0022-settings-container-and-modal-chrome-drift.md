# 设置容器与模态控件语言漂移

## Executive summary

本机设置同时存在游戏外全页和游戏内大型弹层两套容器，导致主菜单打开偏好时离开原上下文；游戏管理层还同时显示侧栏“返回对话”和右上角关闭，尾部 switch 与复位按钮只对齐右边缘而没有共同中心线，默认滚动条轨道又形成额外视觉栏。根因是测试只验证偏好写入、路由可达和关闭后返回，没有把“短暂设置不改 URL”“每层唯一退出”“尾部控件共同中心”和“透明滚动轨道”定义为结构不变量。

## Summary

这些问题没有阻断设置操作，却让同一功能在游戏外与游戏中呈现不同心流：一处像独立目的地，一处像临时工具。管理层内部的两个退出文本表达同一动作，滚动条轨道和未对齐控件又让右侧视觉重量不稳定。

功能测试此前从 `/settings` 直接修改主题，并在游戏管理路由中只点击右上角关闭。它证明了两条路径分别可用，反而固化了双轨；没有断言主菜单设置保持 `/`、弹层只有一个关闭控件、不同宽度尾部控件的中心坐标一致。

## Timeline

1. 本机偏好先以独立 `/settings` 页面提供。
2. 游戏心流重构后，游戏内复用 `SettingsPanel`，但外层改为持久游戏布局上的大型管理层。
3. 管理侧栏保留一个“返回对话”，同时在表面右上角增加关闭按钮。
4. 减少动态效果改为 switch 后与宽度更大的复位按钮继续按行尾对齐。
5. 浏览器默认滚动条在固定高度管理层内绘制明显轨道。
6. 用户在真实设置弹层中发现控件中心不齐、滑轨突兀、退出重复，并指出主菜单设置不应成为全局页面。

## Root cause

复用仅发生在 `SettingsPanel` 内容层，容器语义、退出和滚动表现没有共享契约。路由结构沿用“每个功能一个页面”的资源导航模型，却没有区分设置这种不改变用户当前资源上下文的短暂任务。

设置行使用 `space-between` 把不同宽度控件推到同一右边缘。该规则满足不溢出，却不能产生共同中心线。默认滚动条则没有纳入主题控件语言，浏览器平台样式直接暴露在自绘弹层上。

## Guardrails

- [决策 0053](../decisions/0053-context-local-settings-overlays.md) 固定主菜单本地设置 Dialog、游戏内嵌套设置路由、单一 `SettingsPanel` 和共享模态基础设施。
- Playwright 从 `/` 点击设置后验证 URL 不变、Dialog 可见、Escape 关闭并把焦点恢复给触发按钮；主题跨路由持久化仍从真实主菜单入口验证。
- 游戏管理测试要求弹层内精确存在一个关闭按钮且不存在“返回对话”。
- Playwright 比较 switch 与复位按钮的水平中心坐标；固定尾部控件列保证宽度变化不破坏中心线。
- 模态滚动区域统一使用透明轨道和窄拇指；主菜单设置与游戏设置共同接受 Axe 检查。
