# 会话信息层级再次退化

## Executive summary

游戏页虽然通过了中心轴、固定 composer 和视觉快照门禁，真实页面仍呈现常驻侧栏、密集顶部资源矩阵、巨幅媒体、横向行动胶囊和右侧 Sheet；这些组件各自几何合法，却共同压过了对话主任务。根因是测试把“元素对齐且没有溢出”误当作“信息层级正确”，快照又把同一套错误构图固化为基线。持久教训是：会话体验必须先验证结构排他性、尺寸上限和交互归属，再允许像素基线成为验收证据。

## Summary

玩家进入内置剧本后，需要在窄侧栏的单字或缩写入口、横跨顶部的多项读数、正文、960px 媒体、底部横向建议和右侧资料 Sheet 之间寻找主任务。世界与玩家消息使用过重表面，输入框又被整条底栏包围，使页面像多块工具面板拼接，而不是连续会话。右侧 Sheet 打开时进一步缩小并模糊正文，资料层和会话层无法保持清楚的主次。

## Timeline

1. 游戏布局以中心网格、单滚动区和固定 composer 作为主要几何门禁。
2. 内置剧本继续覆盖 HUD、目标追踪器、工具栏、composer 和暂停菜单，宿主同时保留 AppShell 与资料 Sheet。
3. 视觉矩阵在多种视口上确认元素没有越界，并把现有构图更新为正确基线。
4. 玩家在真实会话中指出侧栏入口不可理解、媒体与气泡过重、顶部层级混乱、右侧资料面板和输入框破坏连续阅读。
5. 游戏内退出 AppShell，宿主收回 composer、资料入口和暂停菜单，五类资料改为居中 Dialog；UI API 收敛为目标与建议 provider 加有限内容槽位。

## Root cause

直接原因是验收指标关注局部几何，不表达全局信息优先级。“唯一滚动区”“多条轴线对齐”“目标未溢出”可以在常驻侧栏、密集 HUD、巨大媒体和横向操作同时存在时全部成立。旧 slot 契约又允许内置剧本重新实现每一层 chrome，所以宿主和剧本都能各自通过组件测试，却没有一个所有者对完整会话层级负责。

快照逃逸的原因是基线只回答像素是否改变，不判断结构是否应该存在；当错误构图第一次被接受后，后续测试只会阻止它意外变化。视觉矩阵还在 settled state 截图，无法覆盖建议写入、预检失效、Dialog 焦点恢复和活动滚动条淡出等交互语义。

## Guardrails

- [决策 0030](../decisions/0030-manus-style-game-workspace-and-ui-api-v6.md) 把默认游戏结构收敛为一个主滚动区、一个会话轴、一个 composer、一个脱离布局的工具栏和居中资料 Dialog，并删除可形成第二套 chrome 的 slot。
- [布局端到端测试](../../e2e/flows/layout.spec.ts) 先断言游戏内没有 AppShell、Sheet 或横向溢出，媒体不超过 720px，会话与 composer 同轴，滚动条只在活动期间出现，再运行视觉基线。
- [真实流程测试](../../e2e/builtins/conversation.spec.ts) 验证五个语义图标入口、目标入口、建议行动写入和聚焦、编辑后预检失效、NPC 人物资料、保存退出与恢复。
- [会话单元测试](../../src/app/ui/game/__tests__/chat-pause.test.tsx) 覆盖预检竞态、Enter、Shift+Enter、IME composing、焦点和 Escape 层级。
- 视觉快照只证明通过结构与语义门禁后的表面没有意外变化，不再作为信息架构正确性的首要证据。
