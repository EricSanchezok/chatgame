# 控件与状态样式的几何漂移

## Executive summary

游戏控制球的三个径向动作使用三组互不相关的手调坐标，中心到控制球的距离分别约为 78、87 和 100px，导致圆形按钮看起来歪斜；减少动态效果直接暴露未定制的原生 checkbox；当前存档高亮则额外增加横向内边距，把整行内容推离其他存档的对齐线。这三个问题都来自把视觉状态当成局部 CSS 效果，而没有为几何不变量、控件语义和状态切换前后的盒模型建立测试。修复将径向动作约束到同一半径和等角圆弧，用具备 switch 语义的开关表示布尔偏好，并通过不参与布局的伪元素绘制当前存档背景。

## Summary

三个界面缺陷同时表现为“控件看起来不稳”：控制球按钮没有共同圆心，设置项混入平台默认 checkbox，当前存档与普通存档不共享同一内容起点。它们都不阻断点击，却破坏了用户判断结构和状态的视觉线索。

功能测试此前只验证三个控制球动作可见且不与状态卡相交、偏好值可以写入、当前存档不能删除。即使按钮落在不同半径、checkbox 与产品控件语言分裂、激活行发生 16px 位移，这些断言仍然全部通过。

## Timeline

1. 控制球从四个动作简化为三个动作，沿用为旧数量手调的径向坐标。
2. 设置页直接使用原生 checkbox 保存减少动态效果偏好。
3. 当前存档通过背景、圆角和额外横向内边距形成卡片强调。
4. 浏览器测试确认动作不越界、管理路由可用和存档操作正确，但没有比较圆心半径或状态行几何。
5. 用户在真实游戏与管理层中发现三个按钮歪斜、checkbox 框选不协调、当前存档内容整体前移。
6. 三个动作改为等半径等角圆弧，偏好改为语义 switch，当前行背景改由绝对定位伪元素绘制。

## Root cause

径向坐标只满足“大致向页面内侧展开”和“不碰卡片”，没有共同半径或角间距这一形状不变量。测试复述了越界和碰撞需求，却没有验证圆弧本身。

设置和存档状态也缺少“状态变化不得意外改变控件语言或布局几何”的共享约束。原生 checkbox 在不同平台和字号下由浏览器自行绘制；当前行的 `padding-inline` 同时承担视觉留白和内容定位，导致高亮必然改变对齐。

## Guardrails

- [决策 0053](../decisions/0053-context-local-settings-overlays.md) 继承并固定三个动作的等半径等角圆弧、减少动态效果的 switch 语义和当前存档的非布局高亮。
- `radialOffsets` 从单一 `radialActionRadius` 推导所有坐标；单元测试遍历左右边缘和三个垂直区域，要求每个动作中心的半径一致。
- Playwright 在真实控制球展开后比较三个按钮中心到球心的距离，同时继续验证视口边界与状态卡碰撞。
- Playwright 通过角色和 `aria-checked` 操作减少动态效果，并使用 Space 验证键盘路径和根节点偏好应用。
- Playwright 使用当前与非当前两份真实存档比较行起点、行宽和正文起点；高亮背景不得通过内边距或边框改变这些值。
