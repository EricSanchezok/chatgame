# 回环地址预览阻断客户端运行时

## Executive summary

桌面预览通过 `127.0.0.1` 打开开发服务器时，Next.js 返回了服务端 HTML，却因开发来源保护拒绝客户端 chunk。页面看似加载成功，实际没有 hydration，剧本库一直停在“正在读取”，按钮也没有交互。错误被误认为数据或 React 状态问题，是因为开发检查只覆盖 `localhost` 和生产 Playwright，没有覆盖桌面预览使用的回环 IP。持久教训是：可见 HTML 不等于应用已启动；本地预览的实际入口地址也必须进入冒烟路径。

## Summary

玩家在 `http://127.0.0.1:32130/scripts` 看到完整页面骨架，但剧本列表为空并持续显示读取状态。终端同时记录 Next.js 拒绝来自 `127.0.0.1` 的开发资源请求。由于客户端 bundle 没有执行，任何修改数据加载 effect 都不能真正修复症状。

## Timeline

1. 开发服务器按默认配置启动，并在 `localhost` 下正常工作。
2. 桌面浏览器用回环 IP `127.0.0.1` 打开同一端口。
3. 服务端页面 HTML 成功返回，Next.js 开发来源保护拒绝该来源的客户端资源。
4. 页面保留 SSR 初始状态，剧本库显示读取中，玩家报告没有剧本和持续报错。
5. 检查开发服务器输出后确认来源拒绝，配置允许桌面预览的精确回环主机并重启，客户端正常 hydration，两个内置剧本立即出现。

## Root cause

直接原因是开发服务器没有声明 `127.0.0.1` 为允许的开发来源。逃逸原因是本地人工检查习惯使用 `localhost`，生产 E2E 使用独立生产服务器，两者都绕过了桌面预览的真实地址；已有页面测试也只验证 DOM 结果，没有验证开发 chunk 是否能从该来源执行。

## Guardrails

- `next.config.ts` 显式允许桌面预览使用的精确回环主机，不使用宽泛通配符。
- 本地交付前从用户实际收到的 URL 打开 `/scripts`，确认状态从读取中变为已安装剧本，并执行一次客户端按钮交互。
- 诊断“页面能看但不能点”时同时检查浏览器控制台、网络中的客户端 chunk 和开发服务器输出，不把 SSR 初始 DOM 当作 hydration 成功证据。
- 生产 E2E 继续验证真实 Route Handler 与 EngineHost；开发来源冒烟作为本地预览补充，而不是替代生产门禁。
