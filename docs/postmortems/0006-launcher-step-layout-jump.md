# 启动器步骤切换首帧跳位

## Executive summary

启动器从剧本介绍横向切换到出身选择时，下一张卡会短暂出现在偏上的坐标，再跳到垂直居中。根因是未激活步骤使用普通 block 布局，只有激活步骤才切换为 grid 居中；横向 transform 与布局模式在同一次状态变更中启动，使浏览器短暂呈现了下一步的旧坐标。稳定原则是：参与同一过渡的所有步骤必须始终共享相同几何布局，交互可用性只由 `inert` 与 `aria-hidden` 控制。

## Summary

玩家点击“开始新游戏”后，出身卡从右侧进入舞台。卡片最终位置正确，但动画开头的顶部坐标不同，在高屏和超宽屏上形成明显的向下跳动。减少动效模式不会暴露该现象，因此只验证最终截图不足以发现问题。

## Timeline

1. 启动器使用三段 flex 轨道与 `translateX` 实现介绍、出身和身份步骤切换。
2. CSS 仅对非 `aria-hidden` 的步骤应用 grid 居中，未激活步骤保留 block 布局。
3. 视觉基线在过渡结束后截图，结构测试也只验证最终卡片与控件存在。
4. 玩家在真实过渡中观察到出身卡首帧偏上并报告问题。
5. 三个步骤改为始终使用 grid 居中，端到端测试新增切换前后顶部坐标不变的几何断言。

## Root cause

直接原因是把视觉布局与可访问状态绑在同一个 `aria-hidden` 选择器上。隐藏步骤仍是横向轨道的一部分，因此它的预布局坐标会参与 transform 过渡；从 block 切换到 grid 导致进入动画包含非预期的纵向重排。

逃逸原因是视觉测试只捕获 settled state，既没有逐帧检查也没有比较过渡前后的目标卡片几何；减少动效与最终 DOM 的无障碍检查同样无法覆盖瞬时跳位。

## Guardrails

- 所有启动器步骤始终使用同一 grid 居中布局，`inert` 与 `aria-hidden` 只负责交互和可访问树，不再改变几何。
- [布局端到端测试](../../e2e/flows/layout.spec.ts) 在点击前读取下一步卡片顶部坐标，切换后要求误差小于一个 CSS 像素。
- 横向步骤过渡的人工验收同时观察动画首帧、进行中和结束位置；最终截图不能替代瞬时几何验证。
